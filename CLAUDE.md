## Что это
Telegram-бот для учёта питания. Пользователь пишет еду свободным текстом, LLM раскладывает её на продукты, граммы, калории и БЖУ, бот сохраняет запись.

## Стек
- Python, pyTelegramBotAPI (telebot), SQLite (`calories.db`), python-dotenv
- LLM: Anthropic API (`claude_client.py`, модель Claude Haiku 4.5), ключ в `.env` (`ANTHROPIC_API_KEY`), токен бота тоже в `.env`
- Windows, виртуальное окружение `.venv`, запуск через `run_bot.bat`

## Файлы
- `bot.py` — хендлеры команд, сообщений, фото и кнопок; черновик приёма пищи и редактор позиций; запуск в `main()`
- `claude_client.py` — `analyze_food()` (текст/фото) и `correct_result()`: запрос к LLM, проверка JSON-ответа
- `nutrition.py` — итоги КБЖУ и пересчёт продукта под новый вес
- `db.py` — таблицы meals, meal_items, weights, known_users, user_states; вся работа с БД (путь — `DB_PATH`)
- `state.py` — состояние диалога (хранится в БД, переживает перезапуск)
- `formatting.py` — тексты сообщений
- `keyboards.py` — инлайн-клавиатуры
- `calc.py` — расчёт нормы калорий и белка
- `reports.py` — отчёты и графики (в памяти, без файлов)
- `reminders.py` — ежедневные напоминания (итог дня / пинок / взвеситься)
- `clock.py` — время в часовом поясе `BOT_TIMEZONE`
- `tests/` — pytest; заглушки Telegram и LLM в `tests/conftest.py`. Запуск: `.venv\Scripts\python.exe -m pytest`
- `test_claude.py` — ручная проверка API (тратит деньги)

## Правила безопасности
- НИКОГДА не выводи, не коммить и не отправляй содержимое `.env`, токены и ключи.
- `calories.db` и бэкапы БД — не коммитить (там данные пользователей).
